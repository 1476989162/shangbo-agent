# 手机远程使用说明

在外网用手机查看会话、发消息、看实时输出、批准高危命令。  
桌面主动外连中转服务，手机也连它，两边都不用开放端口。

## 架构一句话

手机 PWA 与桌面通过中转服务交换**端到端密文**（X25519 握手 + XChaCha 加密），  
中转只转发密文，看不到内容。默认关闭，桌面设置里手动开启、扫码配对。

## 1. 部署中转（你有云服务器）

```bash
cd relay && docker compose up -d --build
curl http://127.0.0.1:8787/healthz
```

然后配 TLS 反代（只接受 `wss://`，拒绝明文），详见 `relay/deploy/TLS.md`。  
假设你的域名是 `relay.example.com`，手机与桌面都填 `wss://relay.example.com`。

## 2. 桌面开启

1. 「设置 → 手机远程」填中转地址 → 打开 **开启手机远程** 开关。
2. 点 **生成配对码**（5 分钟有效、只能用一次），记下配对码与公钥指纹。
3. 远程审批策略按需选择：
   - 允许所有审批（默认）
   - 高危必须回桌面确认（`run_command` / 写文件 / `computer_*` 等回桌面点）
   - 完全只读（只能看不能操作）

托盘图标变绿表示远程在线；托盘菜单可 **一键断开所有远程设备并关闭远程功能**。

## 3. 手机配对

1. 把 `npm run mobile:build` 的产物 `dist-mobile/` 放到中转同目录 `public/`，由同一个 HTTPS 域名托管。
2. 桌面「设置 → 手机远程」点 **生成配对码**，用手机相机或浏览器扫码。
3. 二维码会直接打开 PWA 配对页，并自动填写中转地址、一次性配对码和桌面公钥。
4. 核对页面显示的桌面公钥指纹与桌面设置页一致，点 **配对并连接**。
5. 首次连接成功后按浏览器提示 **添加到主屏幕**。

密钥只存在手机本地（`localStorage`），换手机或清除站点数据后需重新扫码配对。

## 4. 日常使用

- 会话列表、消息历史、发送消息、停止、重新生成：与桌面一致。
- 有待审批时审批区出现 **批准 / 拒绝**；高危命令需二次确认。
- 擦盘/格式化类命令桌面直接拒绝，**不会出现在手机上让你批准**。
- 手机端无设置修改、无供应商/API Key 查看、无文件选择（代码里就没有这些入口）。

## 5. 风险提示（完整版见 `docs/手机远程威胁说明.md`）

- 手机能批准命令 = 拿到手机的人能远程控制这台电脑。手机丢失立即在桌面吊销。
- 中转被攻破只能断网/重放（均被防住），看不到内容、伪造不了审批。
- 长期外出建议开「完全只读」或「高危回桌面确认」。
- Web Push 锁屏提醒为二期；当前版本用前台 30 秒轮询 + 在线推送，PWA 在前台时即时提醒。
- 配对使用 X25519 ECDH + HKDF-SHA256 派生会话密钥；手机只上传公钥，会话密钥不会经过中转。
- 配对二维码包含一次性配对码和桌面公钥，5 分钟失效；生产使用必须确保中转 TLS 证书有效。

## 手工测试清单（发布前逐项勾）

- [ ] 手机用 4G（非 WiFi）连接，在桌面发起任务，手机能看到流式输出并批准。
- [ ] 手机批准 `run_command`（如 `npm test`）后，桌面实际执行。
- [ ] 手机尝试读 `secrets.json`（发 `type secrets.json` 类命令），被桌面拒绝。
- [ ] 吊销手机后，手机立刻断开，重连被拒绝。
- [ ] 关闭远程开关后，桌面不再连接中转（托盘图标恢复，网络抓包无外连）。
- [ ] 正确哈希审批放行；篡改参数后审批被拒绝。
- [ ] 中转重启后，桌面自动重连，手机重新拉取待审批清单。
