# 手机远程威胁说明（必读）

手机能批准命令 = 拿到令牌的人能远程控制这台电脑。本页说清楚：中转被攻破时
攻击者能做什么、不能做什么；手机丢失时怎么处理。

## 信任边界

| 组件 | 信任假设 | 被攻破时的影响 |
|---|---|---|
| 桌面电脑 | 可信（密钥在 safeStorage，审批由人确认） | 全部失守——远程安全建立在桌面可信之上 |
| 手机 | 半可信（人拿着时可信，丢失/被盗后不可信） | 拾获者可批准命令，直到你在桌面吊销 |
| 中转服务 | **不可信**（只负责转发，只见密文） | 见下表 |
| 网络（TLS） | 可信（wss 强制，relay 拒绝明文） | 中间人只能看到密文 |

## 中转被攻破时：能做什么 / 不能做什么

**能做（可用性破坏）：**

- 拒绝转发（手机连不上，桌面显示 reconnecting）
- 掐断/延迟特定帧（审批超时按拒绝处理，不会自动放行）
- 记录连接时间、字节数、IP（元数据泄漏，内容仍是密文）
- 重放旧密文帧（被序号防重放拒绝，见 crypto.ts `recvHigh` 水位 + 1024 窗口）

**不能做（机密性/完整性仍成立）：**

- 看不到会话内容、命令参数、审批理由（XChaCha 密文，中转无密钥）
- 篡改密文（Poly1305 tag 校验失败，client 按解密失败计数，连续 5 次封禁 10 分钟）
- 伪造审批（审批需 `paramHash` 与桌面创建时一致，哈希覆盖完整 `input`，中途替换即按拒绝处理）
- 绕过 `settings:set` 白名单（远程通道根本没有该操作，handler 白名单外一律拒绝）
- 读到 API Key / secrets（`guardPrivatePath` + `commandTouchesPrivateData` 在工具层硬拦，
  且远程无文件选择、无 provider 查询入口）
- 让 CRITICAL 命令执行（擦盘/格式化在 runtime 工具层直接拒绝，不弹窗、不上手机）

## 手机丢失时：桌面吊销（30 秒内完成）

1. 桌面「设置 → 手机远程 → 已配对手机」点 **吊销**（或托盘菜单「立即断开所有远程设备」）。
2. 吊销后：中转立即断开该手机连接，其 `phoneToken` 进黑名单，重连被拒绝。
3. 已发出的待审批不受影响——超时 5 分钟按拒绝处理，不会自动放行。
4. 重新配对需桌面扫码（一次性配对码 5 分钟有效、只能用一次），拾获者无法自行重配。

## 操作建议

- 中转优先自建（`relay/docker-compose.yml` 一条命令启动），地址填自己的 `wss://` 域名。
- 用公共中转时，认准桌面公钥指纹（配对二维码内 `fingerprint`，手机首次配对时核对）。
- 高危场景开「高危必须回桌面确认」：`run_command` / `write_file` / `patch_file` /
  `computer_*` / `mcp__*` 的远程批准一律拒绝，回桌面点。
- 长期外出只读：切「完全只读」，手机只能看不能操作。
- 发现异常连接（托盘显示未知手机在线）：托盘菜单一键断开 + 吊销 + 重新配对。
